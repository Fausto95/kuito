# Naming

Every public name in Kuito, the name Phase 7 gives it, and why. Phase 7 is
one rename, generated where it can be from `src/protocol/manifest.ts`; this
table is its input. Nothing is released, so there are no deprecated aliases:
an old name is removed in the same change that adds the new one.

`test/naming.test.ts` keeps the table complete. It builds the inventory an
app sees — every export of the package's entry points (`kuito`,
`kuito/config` and `kuito/tests`), the members of their module objects and API types, the props
of their props types and native views, and the manifest's typed props and
event props — and fails when a name has no row. A row's first column may name several things that share one
decision.

In the second column, **keep** means the name stays and **remove** means it
goes without a replacement name (the row says what covers it). Every row is
decided.

## Principles

- Names describe Kuito's model. None is kept for familiarity with React
  Native, Expo or Reanimated, and none is renamed only to differ. The test: a
  reader who knows no React Native guesses the behavior from the name.
- One package, `kuito`: apps import every name from it. Its two subpaths
  run outside the app: `kuito/config` types `kuito.config.ts`, and
  `kuito/tests` is the app's tests' API.
- Nouns for things, verbs for actions, adjectives for state.
- No `use*`: scope owns resources (`keepAwake()`, `audio.player()`), released
  when the owning component cleans up.
- No `Async` suffix and no get/set pairs: signals for values that change,
  properties for fixed ones, verbs for actions.
- `watch` for signals and system state, `on` for element events.
- Props take CSS's name where CSS has the concept, and a short platform-neutral
  word elsewhere. Slot props are lower-case nouns (`header`, `footer`,
  `empty`, `separator`). Handlers are named for the fact (`onReachEnd`) and
  pass the value when the value is the fact (`onChange(text)`). Related options
  group into one object (`keyboard={{ dismiss, persistTaps }}`).
- Primitives are named for what they do. Modules are lower-case capability
  namespaces of functions (`haptics.impact()`, `share()`, `alert()`).
- Types follow the value they describe: when `FlatList` becomes `List`,
  `FlatListProps` becomes `ListProps`.

## Props

Native props come from the manifest (`src/protocol/manifest.ts`); the CSS
compiler maps CSS onto them (`docs/styles.md`), so a rename here changes the
compiler's table too. The CSS side never changes: it already speaks CSS.

### Background tasks

`backgroundTasks` keeps the OS's model, not the scope-owned shape of the
other modules: the OS picks when a task runs, may launch the app without UI
to run it, and gives each run a deadline. So a task is `define`d by name at
module scope, where a background launch can find it, and `schedule`d once
from anywhere; the schedule outlives the component, the launch and a reboot,
so no scope owns it, and `cancel` ends it. The names are the schedulers'
where they agree (`schedule`, `cancel`, `deadline`, `requiresCharging`), not
Expo's `registerTaskAsync` and `TaskManager`. Location tasks follow the same
model (`location.defineUpdates`, `location.startUpdates`).
